# Правила режима review

## Классификация

Используй только три понятных типа замечаний.

### Противоречие/ошибка

Примеры:

- два разных размера для одного элемента;
- материал в тексте не совпадает с КД;
- оригинальное наименование/марка материала изменены, переведены или транслитерированы (`INCONEL 601` → `ИНКОНЕЛЬ 601`);
- объект из спецификации используется без ссылки `[поз.N]` или с неверной позицией;
- ссылка на отмененный или неприменимый стандарт;
- порядок операции физически конфликтует с предыдущим шагом;
- способ сварки и указанный норматив не соответствуют друг другу;
- условие приемки противоречит исходному требованию.

### Неоднозначность

Примеры:

- неизвестно, к какому элементу относится действие;
- отсутствует значение, без которого исполнитель выберет его сам;
- `при необходимости` без понятного условия наступления необходимости;
- непонятно, какой из нескольких чертежей определяет размер;
- требование допускает два разных результата;
- контроль указан без достаточного признака приемки, хотя он необходим на этом уровне документа.

### Тяжёлая формулировка

Примеры:

- длинное предложение с несколькими независимыми темами;
- повтор одной и той же инструкции в соседних пунктах;
- канцелярская конструкция, которую можно заменить прямым техническим глаголом;
- чрезмерное дробление одной операции на подпункты;
- список или поднумерация там, где содержание нормально помещается в одну техническую строку;
- пояснение очевидного, мешающее увидеть требование;
- избыточное жирное выделение обычных терминов, параметров или фраз.

## Формат ответа

Группируй только найденные типы. Пример:

`Противоречие/ошибка`
- `п. 4.3 — ...`

`Неоднозначность`
- `п. 5.1 — ...`

`Тяжёлая формулировка`
- `п. 7.2 — ...`

Не исправляй текст и не предлагай новую редакцию, если пользователь отдельно этого не просил. Для нормативных замечаний указывай подтвержденную причину кратко.
