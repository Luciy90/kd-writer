# Архитектура инструкций: абзац, перечисление, список или подпункт

Этот файл обязателен для инструкций по сборке, монтажу и футеровке. Его задача — не дать агенту уйти ни в «всё списком», ни в «всё одной строкой».

## Главное различие

- **Абзац** описывает ход работы.
- **Строковое перечисление** перечисляет простой набор под одним общим действием.
- **Вертикальный список** помогает сверять отдельные записи.
- **Нумерованный подпункт** строит навигацию документа.

Это четыре разные функции. Не используй подпункты как замену абзацам и не используй списки как замену последовательности работ.

## Решение перед форматированием

Для каждого фрагмента пройди вопросы по порядку.

1. Это последовательность действий, условие, подгонка, установка или локальный контроль одного процесса? → **связный абзац**.
2. Это один общий предикат и набор коротких однотипных существительных без индивидуальных значений? → **строковое перечисление**.
3. Нужно сопоставлять каждый элемент со своей позицией, количеством, размером, критерием или пояснением? → **вертикальный список**.
4. Это самостоятельная зона/этап/объект контроля, который должен быть виден в оглавлении или на который полезно ссылаться отдельно? → **нумерованный подпункт**.
5. Ни одно условие пункта 4 не выполнено? → **не создавай подпункт**.

## Нумерация

В полном документе первый раздел всегда `1`. Раздел `0` не создается никогда.

После родительского заголовка разрешен ненумерованный вводный текст. Он не «занимает» номер `x.1`.

Предпочтительно:

```text
4. Контроль качества монтажа
Установленный блок должен иметь устойчивую посадку без качания ...

4.1. Контроль внутреннего одеяла
Проверять ...
```

Менее предпочтительно и допустимо только при реальной необходимости отдельной ссылки на общий блок:

```text
4. Контроль качества монтажа
4.1. Общие требования
...
4.2. Контроль внутреннего одеяла
...
```

Если `Общие требования` относятся ко всем дочерним подпунктам и не имеют самостоятельной функции, убери этот подпункт и перенеси текст непосредственно под раздел `4`.

## Когда текст должен оставаться абзацем

### Хорошо: контроль состояния блока

```text
Перед установкой блок необходимо осмотреть. Не устанавливать блоки со сквозными трещинами, значительными сколами рабочих и сопрягаемых кромок, расслоением, следами длительного увлажнения, выраженной деформацией посадочной поверхности или разрушением зоны крепления. Локальные повреждения заводского защитного слоя при сохранении геометрии и целостности блока допускается устранять с помощью клея КО по п. 4.11.
```

Здесь нет причины создавать отдельный список дефектов: все признаки входят в один запрет и естественно читаются внутри предложения.

### Хорошо: предварительная раскладка и подгонка

```text
Перед окончательной установкой разложить «насухо» центральную группу и ближайшие сопрягаемые блоки без окончательной затяжки крепежа. При несовпадении деталей сначала проверить правильность последовательности и ориентации блоков, равномерность одеяла, положение шнура, наличие посторонних материалов в зоне посадки и фактическую геометрию коллектора. Подгонку выполнять только после определения причины несовпадения.
```

Даже если внутри есть перечисление проверок, это все еще одна последовательная операция. Не превращай ее в каскад `До окончательной установки:` → `При несовпадении проверить:` → вложенный список.

### Плохо: микрошаги вместо абзаца

```text
Нижнее крепление
Установить шпильку ...
Установить шайбы ...
Навернуть гайки ...
Затягивать ...
После смыкания ...
```

Если все строки описывают один крепежный узел, сверни их в один рабочий абзац. Само словосочетание `Нижнее крепление` не делает самостоятельный раздел.

## Когда строковое перечисление лучше вертикального списка

Один общий предикат + простые наименования обычно читаются лучше в строку.

Хорошо:

```text
Рекомендуемый комплект: рулетка, штангенциркуль, металлическая линейка и угольник, уровень и прямолинейная рейка, маркер или мел, гаечные ключи под крепеж M5, ножи, серрейторная пила либо иной инструмент для резки волокнистых огнеупоров, промышленный пылесос, монтажная лента и/или тонкая проволока для временной фиксации одеяла, чистые кисти и шпатели для клея КО, металлическая щетка или другой подходящий инструмент для удаления отслаивающейся окалины, молоток для установки верхних скоб [поз. 9].
```

Похожим образом перечень СИЗ лучше сначала попытаться написать одной фразой: `При монтаже применять защитную каску, защитные очки, закрытую спецодежду с длинными рукавами, защитные перчатки, защитную обувь и средства защиты органов дыхания при операциях с образованием волокнистой пыли.`

Вертикальный список для СИЗ допустим, если его требует форма документа, каждый пункт имеет отдельное условие или список используется как контрольный чек-лист. Само количество элементов не является достаточной причиной.

## Когда вертикальный список действительно лучше

Записи вида `наименование + позиция + количество/размер` оформляй вертикально. Здесь список — почти таблица и нужен для сверки.

```text
Для ориентировочной раскладки на один коллектор номинально приходится:

Блок A [поз. 1] — 4 шт.;
Блок B [поз. 2] — 36 шт.;
Блоки C1/C2 [поз. 3/4] — по 2 шт.;
Блоки E1/E2 [поз. 5/6] — по 2 шт.;
Блок F [поз. 7] — 2 шт.;
Блок G [поз. 8] — 2 шт.;
Скобы [поз. 9] — 50 шт.;
Шпильки [поз. 10] — 50 шт.;
Шайбы [поз. 11] — 100 шт.
```

Не сжимай такие записи в одно предложение через запятые или точки с запятой.

## Не склеивать разные смысловые слои в одно предложение

Даже если фрагмент должен остаться абзацем, не собирай в одно предложение общую геометрию, размеры отдельных элементов, особую компоновку и запрет.

Плохо:

```text
Последовательность блоков по длине коллектора должна соответствовать КД: общие размеры ...; размеры отдельных блоков ...; в центре расположена специальная группа ...; нарушение последовательности не допускается ...
```

Здесь проблема не в самом абзаце, а в том, что одна фраза выполняет несколько разных функций. Раздели ее на несколько законченных предложений внутри одного абзаца. Если набор размеров нужен для построчной сверки, вынеси только этот набор в вертикальный список или таблицу, не превращая в список всю операцию.

## Точка с запятой

Точка с запятой допустима, но не должна создавать искусственное «полуперечисление» из последовательных действий.

Плохо:

```text
При резке ... пыль удалять промышленным пылесосом; не использовать сухое подметание; отходы собирать сразу после образования.
```

Лучше:

```text
При резке и подгонке волокнистых материалов свести к минимуму образование пыли. Резку выполнять в специально отведенном месте или с локальным пылеулавливанием, пыль удалять промышленным пылесосом с высокоэффективным фильтром. Сухое подметание и продувка сжатым воздухом не допускаются. Отходы волокнистых материалов собирать сразу после их образования.
```

Используй `;` прежде всего внутри сложных перечислений, где отдельные элементы уже содержат запятые. Для самостоятельных действий предпочитай точку.

## Когда нужен нумерованный подпункт

Подпункт оправдан, если хотя бы одно из условий выполняется уверенно:

- начинается другой самостоятельный этап монтажа;
- меняется зона/узел, и к ней относится отдельная группа требований;
- меняется объект контроля и под этим объектом есть собственные требования;
- на блок нужно ссылаться из других частей инструкции;
- у него есть равноценные соседние подпункты того же уровня и заголовки ускоряют навигацию.

Подпункт обычно не нужен, если это:

- `Общие требования`, которые относятся ко всему родительскому разделу;
- `Общая последовательность` перед реальными этапами;
- один крепежный узел, описываемый одним абзацем;
- один длинный список комплектности;
- один набор проверок внутри операции;
- один абзац, который не требуется цитировать отдельно.

Если сомневаешься, сначала попробуй абзац под родительским разделом. Подпункт добавляй только когда отсутствие заголовка реально ухудшает навигацию.

## Названия подпунктов

Заголовок должен называться по сути операции, зоны или контроля:

- `Требования к применению клея КО`;
- `Монтаж центральной группы`;
- `Контроль внутреннего одеяла`;
- `Подготовка поверхности`.

Не используй конструкцию `объект — метаописание`:

- плохо: `Клей КО — требования к применению`;
- хорошо: `Требования к применению клея КО`.

Не помещай в заголовок позицию спецификации. Не делай заголовок из полного требования.

## Номенклатура внутри абзаца

Перед черновиком составь карту спецификации. Затем проверь каждое явное упоминание конкретного элемента.

Правильно:

```text
Установить блок G [поз. 17] в рабочее положение.
Разложить блоки E1/E2 [поз. 5/6] и F [поз. 7] без окончательной затяжки крепежа.
Установить нижнее и верхнее крепления [поз. 7/8] согласно КД.
Блоки C1/C2 [поз. 3/4] и E1/E2 [поз. 6/7] рассматривать как отдельные детали соответствующего исполнения.
```

Если полное наименование короткое — используй его. Если оно длинное и мешает чтению, сократи только до однозначной формы, сохранив позицию.

## Пример преобразования списка микрошагов в абзац

Вместо:

```text
1. Перед установкой сверить тип блока с его положением на сборочном чертеже.
2. C1/C2 и E1/E2 рассматривать как отдельные детали соответствующего исполнения.
3. До затяжки крепежа выполнить сухую посадку сопрягаемых блоков.
4. Блок должен устанавливаться без ударного осаживания.
5. Не использовать нижний крепеж для принудительного втягивания неправильно установленного блока.
6. При тугой посадке снять блок и проверить ...
```

Писать связным абзацем, сохраняя отдельные предложения:

```text
Перед монтажом сверить тип блока с указанным на сборочном чертеже. Блоки C1/C2 [поз. 3/4] и E1/E2 [поз. 5/6] рассматривать как отдельные исполнения. Сопрягаемые блоки предварительно установить насухо, без затяжки крепежа, и проверить сопряжение. Осаживание блоков ударами и использование крепежа для принудительного втягивания неправильно установленного блока не допускаются. При тугой посадке блок снять и проверить его тип и ориентацию, состояние контактных поверхностей, отсутствие посторонних материалов и соответствие фактической геометрии коллектора чертежу.
```

Цель — не сделать одно длинное предложение, а убрать искусственную нумерацию там, где читатель воспринимает действия как один рабочий абзац.

## Финальный структурный проход

Перед выдачей инструкции проверь:

1. Первый раздел полного документа — `1`, раздела `0` нет.
2. После родительского заголовка общий текст стоит непосредственно под ним, а не в `x.1. Общие требования` без необходимости.
3. Каждый подпункт отвечает самостоятельной зоне/этапу/объекту контроля или реально нужен для ссылки.
4. Нет микрозаголовков над одним абзацем, если их можно убрать.
5. Последовательные действия написаны абзацами, а не строками-командами.
6. Простые наборы с одним общим предикатом по возможности перечислены в строку.
7. Номенклатура с количеством/позициями оформлена вертикально.
8. Точки с запятой не заменяют точки в последовательных действиях.
9. Каждое явное упоминание конкретной позиции спецификации содержит корректное наименование и `[поз. N]`.
10. Заголовки не содержат позиции и не построены как `Объект — требования к ...`.
