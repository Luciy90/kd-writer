# KD Writer

`kd-writer` — переносимый Agent Skill для написания и редактирования русскоязычной технической документации в области машиностроения, механической КД, футеровок промышленных печей, нефтехимического оборудования и огнеупорного производства.

Архитектура сделана по принципу Sepia: один канонический скилл с маршрутизацией по типу документа и тонкие прямые entry skills для фиксированных операций. Содержательные правила KD Writer написаны специально для технической документации и не наследуют задачу humanizer/de-AI.

## Что умеет

Четыре режима:

- `kd-writer-write` — написать новый текст;
- `kd-writer-review` — проверить без исправлений;
- `kd-writer-refactor` — минимально отредактировать;
- `kd-writer-recreate` — полностью пересобрать из подтвержденных фактов.

Канонический `kd-writer` сам выбирает режим из запроса пользователя.

Поддерживаемые формы:

- технические требования на чертежах и сборочных чертежах;
- общие технические требования к изделию/сборке;
- инструкции по сборке, монтажу и футеровке;
- инструкции/требования по изготовлению;
- контроль, приемка и испытания;
- упаковка, маркировка, транспортирование и хранение;
- пояснительные записки;
- ТЗ и ТУ;
- ремонтные и эксплуатационные инструкции.

## Основные принципы

- российские ГОСТ/ЕСКД как основная нормативная среда;
- самостоятельное определение типа документа по исходнику;
- традиционные короткие формулировки КД;
- связанные требования можно объединять в один пункт;
- недостающие технические параметры не выдумываются;
- блокирующие пробелы уточняются до чистового текста;
- противоречие с обязательной нормой выносится пользователю с вариантами решения;
- ссылки на КД и нормативы оформляются естественно: документ, лист, вид, позиция, пункт;
- объекты из спецификации в рабочих формулировках всегда сопровождаются позицией: `A [поз.1]`, `C1/C2 [поз.3/4]`;
- оригинальные марки и торговые наименования сохраняются буквально: `INCONEL 601` не превращается в `ИНКОНЕЛЬ 601`;
- форма выбирается по содержанию: связная операция пишется абзацем, а длинная комплектность/номенклатура — вертикальным списком;
- жирное выделение используется только для заголовков и редких критичных акцентов; курсив — для редких необязательных примечаний;
- точки с запятой используются по смыслу, но не как способ склеить цепочку самостоятельных действий;
- общий текст родительского раздела инструкции размещается сразу под его заголовком, без искусственного подпункта `Общая последовательность`;
- названия пунктов инструкции не содержат позиции спецификации;
- встроен русскоязычный humanization-pass для удаления AI-слопа и канцелярской воды без изменения технических данных;
- инженерная sanity-check проверка выполняется без самостоятельных расчетов.

## Встроенный humanization-pass

KD Writer использует собственный русскоязычный проход очистки технического текста. Он адаптирован по идеям из:

- `https://github.com/petergyang/no-ai-slop`;
- `https://github.com/smixs/humanizer-ru`.

Второй референс выбран как основной для русской языковой специфики: канцелярит, шаблонные AI-конструкции, пунктуационные костыли и структурная монотонность. Внешняя установка humanizer-скилла не нужна: в пакет включены только собственные правила KD Writer, подчиненные технической точности и стилю КД.

## Частая нормативная база

В `skills/kd-writer/references/standards.md` включены правила применения и проверки:

- ГОСТ Р 2.316-2023;
- ГОСТ 24704-2015;
- ГОСТ Р 59652-2021;
- ГОСТ 5632-2014;
- ГОСТ 5264-80;
- ГОСТ 16098-80.

Важно: ГОСТ 16098-80 не рассматривается как универсальный стандарт для любой коррозионно-стойкой стали. KD Writer должен сначала подтвердить, что речь идет о сварном соединении из двухслойной коррозионностойкой стали.

## Установка

### Универсальная проектная схема для Codex + Gemini CLI

Оба инструмента поддерживают Agent Skills в `.agents/skills/`. Скопируйте содержимое каталога `skills/`:

```text
<project>/.agents/skills/kd-writer/
<project>/.agents/skills/kd-writer-write/
<project>/.agents/skills/kd-writer-review/
<project>/.agents/skills/kd-writer-refactor/
<project>/.agents/skills/kd-writer-recreate/
```

Gemini CLI также понимает `.gemini/skills/`, а для пользовательского уровня — `~/.gemini/skills/` или `~/.agents/skills/`.

### Claude Code

Для проекта скопируйте те же каталоги в:

```text
<project>/.claude/skills/
```

Для пользовательского уровня:

```text
~/.claude/skills/
```

## Рекомендуемый способ использования

Можно использовать только канонический `kd-writer`; это самый переносимый вариант. Прямые entry skills удобны, когда нужно жестко зафиксировать операцию.

Примеры запросов:

```text
Используй kd-writer и напиши технические требования к сборочному чертежу по приложенной КД.
```

```text
Используй kd-writer-review. Проверь инструкцию. Ничего не переписывай.
```

```text
Используй kd-writer-refactor. Сделай формулировки короче, структуру не меняй. Только текст.
```

```text
Используй kd-writer-recreate. Пересобери инструкцию в последовательности фактического монтажа, сохрани все исходные размеры и ссылки на чертежи.
```

## Исходные стилевые ориентиры

При разработке правил использованы предоставленные рабочие примеры:

- монтажная инструкция по футеровке: последовательные операции, ссылки на РП/листы/виды, объединение связанных действий в один пункт;
- сборочный чертеж `3020.03.01-1 СБ`: компактные технические требования по материалам, сварке, термообработке, контролю и специальным условиям.

Эти документы служат ориентиром по плотности, структуре и манере формулировок, но не считаются безусловным нормативным источником. Ошибки, опечатки и спорные технические решения из примеров не должны воспроизводиться автоматически.

## Нормативная проверка

Если агент добавляет ГОСТ, которого нет в исходниках, он должен при доступе к сети проверить его актуальный статус и область применения по официальному фонду Росстандарта. Если проверка невозможна — не утверждать норматив по памяти и не добавлять недостоверную ссылку.
